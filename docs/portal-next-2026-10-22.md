# 入口網下一階段設計：倉庫索引、可擴充版面、各項目視覺化（2026-10-22）

> 起因（使用者 2026-10-22）：
> 「入口網希望加上我的 GitHub 倉庫索引，方便查找 隨著項目越來越多 我要自己在入口網建立倉庫連結越來越費事 系統直接抓取倉庫項目並顯示在首頁就更方便」
> 「入口網UI設計可以不拘泥一整頁不捲動 隨著要顯示的項目變多 要規劃預留或提前想好擴充空間」
> 「入口網各項目視覺化 例如想法庫 我想看到每個想法的來龍去脈 各項目幫我選擇用適合的圖表來呈現」
>
> 依據：2026-10-22 的 `main`（`HomeBoard.tsx` 預覽版、`routes/*`、`HermesIdea` 型別）與 `docs/portal-audit-2026-10.md` §2。**2026-10-22 更新**：§1、§2 已實作（2.47.0）；§3 視覺化尚未做。使用者決定：私有倉庫要顯示（解鎖後）、範圍只算 `chenweihanfool` 帳號、放棄一個畫面並要左側錨點導覽、拿掉手動維護的工具連結（解鎖機制照舊）、子系統連結融進面向卡。

## 1. GitHub 倉庫索引

**做法**：api-server 新增 `GET /api/github/repos`，伺服器端用 GitHub REST（`GET /user/repos`，分頁）抓清單，存進 DB 一列快取（比照 `subsystem_summaries`），每 30 分鐘更新、開頁只讀快取。前端在首頁新增「倉庫」區：搜尋框＋篩選（語言、主題、最近推送、公開／私有）＋卡片（名稱、描述、語言、最後推送、開啟中的 PR 數）。

- 與既有「工具連結」的關係：`portal_sites` 手動連結照舊；倉庫若網址已在 `portal_sites`，卡片上掛「🔗 入口」小徽章，不重複建立。不取代手動連結（不是每個工具都是倉庫）。
- 排序預設「最近推送」，可釘選（釘選存在瀏覽器或 DB，【需決定】）。
- 空狀態與過期：沿用 §2.4 狀態機（資料超過 3× 間隔顯示 dead 與原因）。
- 抓取失敗時保留上一份快取並標 stale，不讓首頁掛掉。

**需要的東西（這是部署設定，Claude 不碰 `.env`，要 HERMES 或你設）**：環境變數 `GITHUB_TOKEN`（fine-grained，**只給 Metadata：Read，加 Pull requests：Read 才有 PR 數**，不給任何寫入權限）。未設定時，退回只抓公開倉庫（未驗證請求每小時 60 次，夠用但抓不到私有）。

**已決定**：私有倉庫要顯示（只在解鎖後）；範圍只算 `chenweihanfool` 帳號。**仍待決定**：PR 數／CI 狀態（需多一組權限與多幾次請求）建議第二期。

**測試**：路由整合測試（200／無 token 降級／GitHub 5xx 保留快取／分頁）、前端純函式（篩選、排序）單元測試。

## 2. 版面：從「一頁放得下」改成「可捲動、可長大」

現況：`DesktopBoard` 是電腦版一畫面放 6 卡；`HomeBoard`（`#home` 預覽，2.35.0）已經是 §2.6 的五段式、可捲動。**建議直接以 `HomeBoard` 為基礎擴充，不再維持單畫面限制**，並把「新增一個區塊」變成加一筆註冊資料：

```
┌ 頂列：問候＋幸福指數一句話＋搜尋(⌘K) ┐   ← 固定在上，捲動時縮小
├ 左側錨點導覽(電腦版，sticky) │ 區塊(可捲動) ┤
│  今天                       │ ① 今天
│  面向                       │ ② 六面向小卡
│  成長                       │ ③ 成長軌跡
│  好玩的                     │ ④ 想法庫／美食
│  倉庫  ← 新                 │ ⑤ 倉庫索引        ← 新，預留
│  系統                       │ ⑥ 系統燈號
│  ＋（預留：更多區塊）        │ ⑦ …
└ 手機：頂部橫向錨點列，區塊上下堆疊 ┘
```

- **區塊註冊表** `SectionDef { id, title, icon, order, minRole, expectedEveryMin, render, fetch? }`：新增區塊只加一筆；導覽、錨點、折疊狀態、載入狀態全部由註冊表生成。這也是把 `App.tsx`（3500 行）拆檔的切入點（audit §2.7 已寫過同一想法，這次落實）。
- **折疊與記憶**：每區塊可折疊，狀態存 `localStorage`（讀寫包 try/catch，失敗不影響顯示）。
- **懶載入**：區塊進入視窗才抓資料與載入元件（`IntersectionObserver`＋`React.lazy`）。順便解掉 #108 的 bundle 問題（three.js 只在 `#nebula` 載入）和首頁一次打十幾支 API 的負擔。
- **網格**：`grid-template-columns: repeat(auto-fill, minmax(280px, 1fr))`，卡片數量變多時自然換行，不靠寫死的 6 格。
- **預留空間**：註冊表尾端留「＋更多」，區塊超過 ~8 個時導覽自動收成可展開的清單。
- **保留**：深色風格、`useCountUp`、減少動態設定、既有抽屜與全頁（`#graph`、`#food` …）不動。
- **風險**：`DesktopBoard` 有既有 e2e（197 項），切換預設首頁前要先讓 `HomeBoard` 通過同一批巡檢；切換用旗標（`#home` 預覽 → 預設），可退回。

**【需決定】**：(1) 是否同意放棄「電腦版一畫面放得下」；(2) 左側錨點導覽要不要（會佔寬度；另案可只用頂部列）；(3) 現有左側的工具連結欄是否維持常駐。

## 3. 各項目視覺化（選圖依據：`portal-audit` §2.2 的指標類型表）

### 3.1 想法庫：每個想法的來龍去脈

資料其實已經有（`HermesIdea`）：`bornAt`、`days[]`（出現過的日記日期）、`history[]`（狀態變化與時間）、`mentions`、`mergedInto`／`absorbed`、`category`、`source`、`why`、`value`／`effort`。**不需要改 HERMES 端**；缺的是日記原文出處，可用既有 `/hermes-doc` 以日期點進去（第二期）。

| 視圖 | 圖表 | 回答的問題 | 資料 |
|---|---|---|---|
| 單一想法的「生命線」（點開某個想法顯示） | **水平時間軸**：橫軸＝時間；上方圓點＝每次被想起（`days`），下方階梯線＝狀態變化（`history`），終點標「已實行／擱置／併入」 | 這個想法何時出現、被想起幾次、卡在哪、怎麼結束 | `bornAt`、`days`、`history` |
| 想法之間的血緣 | **樹狀（承接→被併入）**，只對有 `mergedInto`／`absorbed` 的想法顯示 | 誰併進誰 | `mergedInto`、`absorbed` |
| 全部想法一覽 | **泳道圖**（每想法一列，沿用生命線的縮小版，依類別分組，可依狀態篩選） | 哪些想法是新的、哪些放很久、哪些在進行 | 同上 |
| 該先做哪個 | **價值×難度散佈圖**（四象限：快贏／大案／雜務／避開），點大小＝被想起次數，顏色＝狀態 | 前三名為什麼是它們 | `value`、`effort`、`mentions` |
| 流向 | **桑基圖**：新→評估→進行→已實行／擱置／放棄 | 想法大多卡在哪個階段 | `history` 彙總 |
| 節奏 | 近 12 週「新增 vs 實行」長條（已有）＋ **日曆熱圖**（哪天想法多） | 什麼時候最會冒點子 | `weeks`、`days` |

首期做前兩項加散佈圖（單一想法的生命線＋血緣＋價值×難度），其餘排後面。
